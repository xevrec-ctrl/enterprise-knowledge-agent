# 企业知识库 Agent 面试讲解稿

这份材料用于复习，不建议逐字背诵。面试时只讲自己实际运行、修改和验证过的内容。

## 一分钟介绍

我基于 LangChain 官方 ReAct Agent 模板二次开发了一个企业知识库与任务协同 Agent。
原模板只有通用搜索工具和“模型—工具”循环，我把它改成了中文企业场景：加入 Markdown
知识库切分和 BM25 检索、带来源的结果格式、任务草稿工具，以及一个引用检查节点。
当问题涉及公司制度时，模型先调用检索工具，再根据证据回答；如果最终答案漏了来源，
LangGraph 会要求模型修正一次。当前版本主要用于验证工作流，后续准备加入 PDF/Word
解析、向量检索和评测集。

## 面试官可能追问

### 这和普通 RAG 有什么区别

普通 RAG 往往是固定地“检索一次再生成”。这个项目让模型通过 Tool Calling 判断是否需要
检索或生成任务草稿，并在工具执行后继续推理。另外，最终回答还经过独立引用检查节点，
不是把所有逻辑都塞进一个 Prompt。

### LangGraph 在哪里起作用

`call_model` 节点负责模型推理，`tools` 节点负责执行检索和任务工具，条件边根据模型是否
产生 tool call 决定下一步。没有 tool call 时进入 `citation_guard`；知识库回答缺少来源就
回到模型修正，否则结束。

### 为什么 V0.1 不直接用向量数据库

我先用本地 BM25 建立可重复的基线，单元测试无需联网和 API Key，能先验证文档切分、
来源格式和图路由。下一步再加入向量检索，与 BM25 做混合召回和效果对比，而不是一开始
堆很多基础设施却无法判断改进是否有效。

### 中文 BM25 是怎样处理的

简单按空格切分不适合中文，所以我生成单字和双字 token，英文和数字按连续字符串处理。
它不是专业中文分词的最终方案，但依赖少、行为可测试，适合第一版基线。

### 如何减少模型胡编

系统提示要求制度类问题必须先检索；工具没有结果时返回明确的 `found: false`；有结果时
提供正文和统一来源标记；最后引用检查节点确认答案保留来源。它不能完全消除幻觉，但能
让无依据回答更容易发现和追踪。

### 你实际改了什么

我重新设计了业务场景和提示词，写了 Markdown 加载与 BM25 排序逻辑，定义了检索与任务
草稿两个工具，修改了 LangGraph 图并加入引用检查，增加了示例资料、测试和中文文档。
模型接入和部分代码实现使用 AI 辅助，但我通过单元测试和手工问题验证了关键行为。

### 项目目前有什么不足

只支持 Markdown；BM25 无法充分理解同义表达；没有持久化会话、权限控制和可视化界面；
引用检查只验证“是否存在来源标记”，尚未验证结论是否真的由该证据支持。这些也是后续
迭代方向。

## 演示顺序

1. 先问报销材料，展示知识库工具调用和带来源回答。
2. 再问知识库不存在的年终奖规则，展示拒绝编造。
3. 输入一个模糊工作目标，展示任务草稿及 `draft` 状态。
4. 打开 LangGraph 图，解释模型、工具和引用检查三个节点。
5. 运行离线测试，证明检索和路由行为可以重复验证。

## 不要这样说

- 不说“项目已在企业生产环境上线”。
- 不说“自主研发了 LangGraph 或 RAG 框架”。
- 不说“完全解决了大模型幻觉”。
- 没有实际完成 PDF、向量数据库或 Web 界面前，不把它们描述成已完成功能。
